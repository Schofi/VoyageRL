# 面试讲解指南

下面的讲解提纲与代码入口对应，个人贡献与实验结果可按实际完成情况补充。

## 两分钟介绍

> VoyageRL 围绕旅行规划任务整理了一条智能体实验链路：从问题扩充和教师轨迹蒸馏，到格式与质量清洗，再接入 SFT 和 GRPO，最后做多轮工具推理与双向模型评估。
>
> 我重点关注的是工具交互的可执行性。模型输出需要经过协议解析，再调用天气、地图、搜索等工具，返回信息进入下一轮上下文。推理端对非法调用、重复调用和最大轮次设置边界；训练调度器复用推理解析函数，奖励也按同一解析口径判断，减少训练时奖励了、推理时却不能执行的情况。
>
> 工程层面，可以沿着数据续跑、请求预算和遥测三个点展开：蒸馏只跳过通过完整性校验的结果；问题扩充有明确请求与数量上限；推理记录模型和工具耗时、调用错误与 token 估算。具体哪些改动由我承担，应结合提交和实际工作说明。
>
> 当前公开仓库可以运行离线测试，但完整 GPU 训练和模型效果尚未重新验证；票务工具是模拟实现。我会把可运行代码、已验证行为和待验证训练假设分开介绍，不用未复现的数字证明效果。

## 技术追问与代码证据

| 追问 | 可以展开的回答 | 代码入口 |
| --- | --- | --- |
| 为什么不只让模型直接回答？ | 旅行信息具有时效性；工具用于获取外部证据，但工具失败和信息质量仍需处理 | `tools/`、`run_tool_loop_infer.py` |
| 如何避免工具循环失控？ | 轮次上限、非法调用重试、相同调用签名识别、强制回答等机制；说明它们约束成本而非保证正确性 | `run_tool_loop_infer.py` |
| 为什么复用解析器？ | 训练调度器和奖励读取同一套调用/答案解析逻辑，降低协议定义不一致；仍需真实框架集成测试 | `training/plugins/` |
| 为什么需要六项奖励？ | 过程、schema、答案标签、阶段、效率、答案评审分别提供信号；规则项与质量项可能冲突，需要消融 | `tooluse_reward_parser_aligned.py` |
| 断点续跑怎么判断完成？ | 校验保存的样本身份、轨迹和有效答案，而非仅判断文件存在；原子保存减少中断损坏 | `data_distill.py` |
| 怎样控制扩充费用？ | SDK 隐式重试关闭，设置最多请求数、连续无进展退出及总条数上限 | `test_expand_50.py` |
| 为什么做双向评估？ | 交换候选与参考顺序后平均，降低位置偏差；仍不等于消除模型偏见 | `llm_judge.py` |
| 怎么定位延迟？ | 对比模型阶段、工具阶段和端到端耗时；当前没有 TTFT/TPOT，token 是重新分词估算 | `utils/inference_telemetry.py` |

## 现场演示顺序

1. 展示 README 的流程与限制，说明不含模型权重及私有训练数据。
2. 运行离线测试，展示有界扩充、续跑和遥测的测试用例。
3. 打开合成天气输入，沿解析器、工具和答案终止条件走读一次控制流。
4. 打开调度器和奖励插件，说明与推理共用的逻辑和 ms-swift 接口边界。
5. 有真实模型环境时再运行单条推理，展示真实生成的输出；没有时只展示代码，不把示例输入说成演示结果。
