# 验证与评估说明

本次整理验证的是代码与仓库可用性。公开版本没有新生成的训练效果表，也没有可据此声称 SFT 或 GRPO 提升了多少的实验结果。旧数据与笔记保留在被忽略的本地目录，不能当作此次重跑证据。

## 已有验证的含义

离线测试入口为 `python -m pytest -q`；测试目录由 `pytest.ini` 限定为 `tests/`，根目录的 `test_expand_50.py` 是真实模型调用脚本，不属于这组离线测试。

| 测试文件 | 覆盖重点 |
| --- | --- |
| `tests/test_expansion_50.py` | 去重、请求预算、失败退出和最多 50 条边界 |
| `tests/test_data_distill.py` | 结果完整性、断点续跑与 token 用量处理 |
| `tests/test_train_ticket.py` | 火车票工具参数与模拟服务行为 |
| `tests/test_inference_telemetry.py` | 耗时、token 估算、错误分类与日志写入 |
| `tests/test_inference_monitor_integration.py` | 推理循环接入遥测后的成功/失败路径 |

2026-10-23，在新建的 Python 3.11 虚拟环境中安装 `requirements/dev.txt` 后，运行 `python -X utf8 -m pytest -q`，得到 **71 passed in 3.10s**，`pip check` 也通过。六个 Bash 启动器通过语法检查。测试使用替身隔离模型、GPU 与外部服务；这不是 71 条旅行任务评测，也没有覆盖完整训练插件的真实 ms-swift 集成。

尚未验证：完整 GPU 依赖安装、真实模型推理、外部服务可用性、SFT/GRPO 端到端运行和规划效果提升。

## 指标口径

| 字段 | 含义 | 不能推导的结论 |
| --- | --- | --- |
| `success` / `status` | 推理是否以答案状态结束 | 答案事实正确、预算满足或用户满意 |
| `e2e_s`、`model_s`、`tool_s` | 请求总时长及模型/工具阶段累计耗时 | 并发吞吐或服务容量 |
| `tool_calls`、`tool_errors` | 调用次数及已识别协议/运行错误 | 返回信息一定有用或完整 |
| `output_tokens` | 对生成文本重新分词得到的估算 | 供应商账单、完整上下文 token 或精确生成性能 |
| `ttft_s`、`tpot_s` | 当前保持空值 | 首 token 延迟或逐 token 延迟 |

蒸馏中的服务端 usage 和推理中的重新分词估算不是同一口径，报告时应分别注明来源。指标采集只写统计字段，不写问题与回答正文。

## 双向模型评估

[llm_judge.py](../llm_judge.py) 用相同评审模型分别比较 A/B 与 B/A，交换顺序后平均分数，降低位置偏差。它按 `query` 文本匹配两组完整轨迹，只评估交集；重复问题会覆盖，遗漏问题不会自动进入评分。

双向打分不能消除评审模型偏好、事实判断错误、参考答案错误或测试集泄漏。请固定评审模型和提示词版本，记录失败样本，结合人工核验，避免把自动分数当成真实旅行体验。

## 建议实验设计（尚未执行）

1. 固定测试问题、模型版本、工具配置和采样参数，区分实时查询日期。
2. 比较基础模型、SFT、SFT+GRPO；模型规模与推理预算保持可比。
3. 除自动评审分数外，记录完成率、工具失败率、约束满足率、耗时和调用成本。
4. 做奖励消融：去掉效率项、固定阶段权重、去掉答案评审，分别验证各项作用。
5. 单独分析格式错误、重复调用、工具失败、无证据回答和交通模拟内容误用。
6. 报告有效样本量、失败/缺失数量和多次运行波动；没有测量的字段留空。

保留每次运行的命令、最终环境变量、依赖版本、模型与数据标识、硬件配置及原始结果。只有完成这些实验后，才适合在简历或 README 中写具体效果增益。
